编排结果通过结构化契约流转。规划告诉系统“如何做”，派发明确“谁来做、边界是什么”，回流交付“完成了什么、依据是什么”。

## 证据等级

| 等级 | 含义 |
| --- | --- |
| A | 直接验证 |
| B | 多源一致 |
| C | 单源或旁证 |
| D | 推断 |

证据等级用来区分结论的依据类型，不等同于模型自报的置信度。没有完成验证时，应保留不确定性与验证条件。

## OrchestratorPlan

指挥体规划包含路由等级、目标、边界、验收条件和节点清单。以下是精简示例：

```json
{
  "routeLevel": "L2",
  "goal": "分析配置模块并提出改进方案",
  "boundary": {
    "inScope": ["配置模块"],
    "forbidden": ["修改生产配置"]
  },
  "acceptance": ["每项结论带来源与风险说明"],
  "nodes": [
    {
      "id": "T1",
      "title": "检索配置调用链",
      "agentIdentifier": "research",
      "objective": "确定配置读取与写入路径",
      "acceptance": ["列出验证过的调用入口"],
      "dependsOn": [],
      "priority": "P1"
    }
  ]
}
```

### 路由等级

- `L0`：直接作答，不生成派发节点。
- `L1`：单链任务。
- `L2`：并行任务。
- `L3`：包含裁决的任务路径。

节点的 `agentIdentifier` 必须来自当前组可调度的个体清单。单个智能体目标使用直接服务路径。

## DispatchOrder

派发单携带任务节点与执行上下文：

- 目标、边界、验收口径与工具白名单。
- 上游 SyncReport 摘要和依赖状态。
- 当前个体私有记忆与群体共享记忆。
- 命中的技能指令与协议内容。
- 步数、超时等运行限制。

派发单负责固定任务职责，使子个体不必从模糊对话中重新猜测工作范围。

## SyncReport

回流围绕五项信息组织：结论、证据等级、风险、阻塞与置信度。以下为概念清单，具体字段以仓库 schema 为准。

| 项目 | 需要回答的问题 |
| --- | --- |
| 结论 | 完成了什么，未完成什么？ |
| 证据 | 哪些来源或验证支撑该结论？ |
| 风险 | 影响面与回退路径是什么？ |
| 阻塞 | 什么条件阻止继续执行，如何解除？ |
| 置信度 | 对当前判断有多确定，哪里仍需验证？ |

运行时同时校验结构和业务口径。校验失败时可以要求重写；持续失败或出现分歧时，升级指挥体处理。

## 冲突与裁决

两个子个体结论不一致时，系统保留分歧与各自依据，并按需追加裁决节点。裁决需要记录选择理由与相关风险，再进入收束流程。

## 事件与接口

REST 提供状态查询与管理入口，WebSocket 广播运行事件。工具调用、执行结果、审批和任务终态能够关联到会话与任务图。

完整 API、实体字段与存储布局较长，请查阅[仓库协议文档](https://github.com/ExMachina-Project/ExMachina/blob/dev/docs/协议与契约.md)。这里的示例帮助理解运行机制，不替代当前版本的完整 schema。
